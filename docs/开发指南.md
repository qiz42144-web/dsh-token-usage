# 开发指南

面向想改代码或提 PR 的人。使用说明见 [使用指南](使用指南.md)。

---

## 1. 结构

```
dsh-token-usage/
├── index.js              Host 入口：打开数据库、注册事件监听与 HTTP 路由
├── client.js             前端全部代码（React 组件 + CSS，单文件）
├── lib/
│   ├── db.js             SQLite schema、语句、迁移
│   ├── recorder.js       把 session/event 写成请求行
│   ├── usage.js          usage 归一化（含未知处理）
│   ├── query.js          聚合查询：summary / trend / rankings / records
│   ├── time.js           范围与粒度计算
│   ├── settings.js       settings.json 读写
│   └── api.js            RPC 分发
├── locale/               en.json / zh.json
├── cordis.patch.yml      bundle 补丁：插入 Host 行
├── test/                 自动化测试 + 合成夹具
├── dev/                  开发与验收脚本
└── docs/                 文档与截图
```

### 两半

- **Host 半**（`index.js` + `lib/`）跑在 Electron 主进程，用 `node:sqlite` 的 `DatabaseSync`
- **Client 半**（`client.js`）跑在渲染进程，通过 `window.__ModuleLoader__` 注入，只 `require('react')`

两者通过同源 JSON RPC 通信：`POST /dsh-token-usage/api/v1/rpc`。

---

## 2. 数据流

```
DSH 提交会话事件
   ↓ session/event
recorder.handle(session, event)
   ↓ 只处理 assistant/message 与 step/end
INSERT INTO requests … ON CONFLICT(id) DO NOTHING
   ↓
query.js 聚合
   ↓ RPC
client.js 渲染
```

去重键是 `msg:<sessionId>:<seq>` 或 `step:<sessionId>:<seq>`，所以重放事件不会重复计数。

## 3. 本地开发

### 跑测试

```bash
node --test test/*.test.mjs
```

118 个测试，覆盖：usage 归一化、时间范围与粒度、聚合查询、API 契约、设置持久化、前端渲染与交互。

前端测试用 `test/mini-react.mjs`——一个极小的 React 替身，会强制检查 Hook 调用顺序（这正是当初 React #310 白屏的根因）。

### 对运行中的实例验收

```bash
node dev/verify-live.mjs http://127.0.0.1:4551
```

53 项检查，直接打真实接口，验证返回结构与数字自洽。

## 4. 改前端

`client.js` 是单文件，包含：

- 两个语言字典 `DICT_EN` / `DICT_ZH`（**键必须完全一致**，有测试保证）
- 纯函数：`bucketParts`、`axisTicks`、`heatCells`、`placeTooltip`、`calendarCells` 等
- 组件：`Metric`、`TrendChart`、`Ranking`、`DatePicker`、`CalSelect` 等

### 注意事项

1. **Hook 顺序**：所有 Hook 必须在任何 `return` 之前调用。早退分支里再调 Hook 会触发 React #310。
2. **不要用 `title` 属性做提示**：会和自绘气泡重复，用 `role="img"` + `aria-label`。
3. **颜色走变量**：`--tu-accent`（`#35CFE3`）、`--tu-success`、`--tu-warn`、`--tu-danger`，其余用 `--dsw-alias-*`。
4. **不要加 `!important`**：新样式只作用于自己的类名。
5. **动画要能收起**：弹层用 `visible` / `entered` 两段状态，收起动画播完再卸载节点。

### 改完怎么验证

```bash
node --test test/*.test.mjs
```

然后重载插件（`plugin_manager` 关掉再打开），在真实窗口里看一眼。

## 5. 改后端

`lib/query.js` 里的聚合 SQL 用 `BUCKETS` 常量生成时间分桶表达式。注意：

- 别名不能叫 `hour`，会和 SQLite 的残留列名冲突
- 小时桶用 `strftime('%Y-%m-%dT%H', ts / 1000, 'unixepoch', 'localtime')`
- 改 schema 必须同时提升 `SCHEMA_VERSION` 并写迁移

## 6. 截图

文档截图必须用合成数据，且不能包含侧边栏会话标题、其他插件或本机路径。

```bash
node dev/make-demo-db.mjs            # 生成 dev/synthetic/usage.db
```

然后把插件临时指向它（在 profile 的 `cordis.patch.yml` 里加 `dbPath`），重载插件，截图，最后**恢复配置并重载**。

截图裁剪到只保留插件面板，存到 `docs/images/`。

## 7. 发布流程

仓库有两个独立历史：

- `main`：本地开发分支，包含真实数据夹具的历史
- `public-main`：公开快照，**根提交，无父提交**

**只发布 `public-main`**：

```bash
git checkout public-main
git checkout main -- .          # 同步最新代码
git status                      # 确认没有 real-usage.json / 截图 / db
node --test test/*.test.mjs     # 必须全绿
git commit -m "chore: sync public snapshot"
git push origin public-main:main
```

两个历史没有共同祖先，**不能 merge**。禁止 force push。

---

## 8. 提交前检查

```bash
git status                      # 没有 db / settings.json / 截图
git diff --cached --stat        # 改动符合预期
node --test test/*.test.mjs     # 全绿
```

确认没有把真实 Provider 名、真实模型 id、真实用量或本机绝对路径带进代码、测试或文档。

---

## 9. 依赖

运行时零第三方依赖，只用 Node 内置的 `node:sqlite`。请不要为了一个小组件引入 UI 框架或日期库。
