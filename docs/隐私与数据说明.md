# 隐私与数据说明

这个插件处理的是用量数字，不是对话内容。本文说明它到底读了什么、存了什么、存在哪、怎么删。

---

## 1. 数据来源

DSH 在每次会话事件提交后会发出 `session/event`。对每个模型步骤，其中有一条 `assistant/message` 事件，携带：

```json
{
  "type": "assistant/message",
  "seq": 17,
  "time": 1793386668602,
  "data": {
    "turn": 1,
    "step": 1,
    "message": {
      "source": { "kind": "model", "provider": "provider-a", "model": "model-alpha" }
    },
    "usage": {
      "inputTokens": 20525,
      "outputTokens": 172,
      "totalTokens": 21209,
      "cacheReadTokens": 512
    }
  }
}
```

插件只读这几个字段：`type`、`seq`、`time`、`turn`、`step`、`message.source`、`usage`。

**它不读**：`content`、工具调用参数、请求体、响应体、任何凭据。

---

## 2. 存了什么

每条模型步骤一行，字段如下：

| 字段 | 说明 |
|---|---|
| `session_id` | 会话 id（用于去重） |
| `seq` | 事件序号（用于去重） |
| `turn` / `step` | 轮次与步骤 |
| `ts` | 时间戳 |
| `day` / `week` | 预计算的时间列，用于分组 |
| `provider_id` / `account_id` / `model_id` | 身份标识 |
| `input_tokens` / `output_tokens` / `cache_read_tokens` / `cache_write_tokens` / `reasoning_tokens` / `total_tokens` | 用量 |
| `usage_known` | 该行是否有真实 usage |
| `source` | `message` 或 `attempt` |

**没有**提示词、回复、工具参数、请求体、API Key、账号密码。

### 去重

同一会话的同一 `seq` 只会写入一次（`INSERT … ON CONFLICT(id) DO NOTHING`），所以重放事件不会重复计数。

---

## 3. 存在哪

| 文件 | 内容 |
|---|---|
| `$DSH_HOME/token-usage/usage.db` | SQLite 历史数据库 |
| `$DSH_HOME/token-usage/settings.json` | 数字格式、上次范围、显示选项 |

`$DSH_HOME` 默认是 `%USERPROFILE%\.dsh`（Windows）或 `~/.dsh`。可以用配置项 `dbPath` 改到别处。

数据库使用 WAL 模式，所以同目录下还会有 `usage.db-wal` 和 `usage.db-shm`。

---

## 4. 网络

**没有任何出站请求。**

插件里唯一的 `fetch` 在 `client.js`，是前端页面调用本机 Host 的接口：

```
POST http://127.0.0.1:<port>/dsh-token-usage/api/v1/rpc
```

Host 侧只注册了一个本地 HTTP 路由，不连接任何外部服务。

---

## 5. Token 消耗

**零额外消耗。**

- 不调用模型
- 不注册工具（不占工具定义）
- 不往提示词里注入任何内容（不占上下文）

它只是在请求完成之后，把已经写好的用量数字抄一份到本地数据库。

---

## 6. 删除数据

**只删历史，保留插件**

```bash
rm -rf "$DSH_HOME/token-usage"
```

插件下次启动会重新建库，从那一刻开始记录。

**只删插件，保留历史**

```
plugin_manager remove_bundle  target = dsh-token-usage
```

数据库不会被删除。

**彻底清除**

先卸载插件，再删除 `$DSH_HOME/token-usage/` 目录。

---

## 7. 关于测试数据

仓库里的 `test/fixtures/usage-events.json` 是**合成数据**：

- 由 `test/build-fixture.mjs` 用固定种子的伪随机生成器产生
- Provider 是 `provider-a`…`provider-d`，模型是 `model-alpha`…`model-delta`
- 时间范围固定在 2026-03-02 至 2026-03-15
- 不含任何真实会话、真实 Provider、真实模型或真实用量

README 里的截图同样使用合成数据：由 `dev/make-demo-db.mjs` 生成一个临时数据库，把插件指向它之后截图，截完即恢复。截图经过裁剪，只保留插件面板本身，不含侧边栏会话标题、其他插件或本机路径。

---

## 8. 仓库里不会出现的东西

`.gitignore` 明确排除：

- `*.db`、`*.db-wal`、`*.db-shm`、`*.sqlite`
- `settings.json`
- `*.log`、`*.tmp`、`*.bak`
- `dev/screenshot-*.png`、`dev/shot-*.png`、`dev/demo-*.png`
- `test/fixtures/real-usage.json`（从真实日志提取的夹具，仅本地保留）
- `dev/synthetic/`（截图用的临时数据库）

如果你要提交改动，提交前请确认 `git status` 里没有上述文件。
